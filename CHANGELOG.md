# Changelog

## Unreleased

- Everything Hesperus writes lands under `<repo>/.hesperus/`, which gets a `.gitignore` of `*` so the folder ignores itself: `hesp init` and **Create Intent From Code** write the intent there (was the repository root), `hesp emit` defaults to `<repo>/.hesperus/actual` (was the current directory), and the extractor's caches add the same file. The repository's own `.gitignore` is no longer edited. The extension and the language server find an intent inside `.hesperus`.
- The Rust side follows the pivot: `hesp diff` and the core differ are gone; `hesp emit` writes only `.hesperus/actual/flow.json` and prints its path; `hesp init` writes the intent, then the flow, and reports the entry count; the language server no longer flags generated files or refuses to rename in them.
- **Flow is the only view.** The Intent, Actual and Unified graph modes are gone, with the diff plumbing in the extension and the sidebar's diff counts. The intent file keeps three roles: bindings (which component a file's functions belong to), boundary names, and `require`/`forbid` constraints; its edges are no longer read. The viewer shows one entry point as a pipeline, lists the entries, the entries that pass through the file open in the editor, and the constraint results; Ctrl/Cmd-click opens the owning component in `.hesp`.
- **Queries and an MCP server.** `hesperus-ts entries | flow <entry> | reaches <file[:line]> | boundaries --since <rev> | check` answer, as text or `--json`: what the entry points are and what each touches; what one entry does, call by call; which entries a file or line sits under; what the working tree newly reaches outside the program compared with a revision (new hosts, store writes, filesystem or process use per entry, new or removed entries, constraints that changed); whether the constraints hold (exit 1 on a violation). `hesperus-ts mcp <repo>` serves the same tools on stdio. The flow is cached in `.hesperus/actual/flow.json` while it is newer than every source file; each revision's flow is cached by commit. `skill/SKILL.md` is the workflow.
- **Trace rows.** Router mounts prefix their routes (`app.use("/api", r)`); a route with several handlers is one entry with a `next` chain; `Bun.serve({ routes })` objects give one entry per path; functions handed to timers and cron schedules are `timer` steps; `.on(name, fn)` on an emitter (and `addEventListener`) is an `event` entry and `.emit(name)` reaches its handlers; `process.env.X`, `Bun.env.X`, `import.meta.env.X`, `Deno.env.get("X")` are `config` crossings; pathname comparisons inside one handler are one entry with the other routes under `also`.
- Constraints are checked in the flow over every function in the repository, with witness sites and the entries that pass through them (`flow.json` 0.2: `components`, `constraints`, unit end lines). Goldens compare modulo CRLF.
- **Flow**: a fourth viewer mode. `hesp emit` (and the extension's Emit) also writes `.hesperus/actual/flow.json` (shape: `docs/flow.schema.json`): for each entry point the extractor finds (route handlers, `main`, `bin`/shebang modules, CLI command handlers, VS Code `activate`), the functions it reaches in source order and the stores, hosts, filesystem and processes where each path leaves the program. The viewer draws one entry as a left-to-right pipeline, functions tinted by their owning component; the inspector lists the entries; clicking a step opens its source line. `hesperus-ts flow <repo>` prints the same JSON. Depth and step caps keep it bounded; cycles and repeats are marked, not expanded.
- The extractor nests unbound code by directory: `apps/web/x.ts` is a component `web` inside a subsystem `apps` (was a flat `apps_web`), so an emitted or `init`-generated repository reads as subsystems from the start.
- Viewer: the wheel zooms about the pointer (shift-wheel pans); the layout folds long dependency chains into a grid that fits the panel, and re-fits when the panel is resized or the inspector toggled; neighbouring boxes in a column connect with straight vertical arrows.

- **Hesperus: Create Intent From Code** and `hesp init`: describe a repository already under way as an intent that matches its actual exactly, then track changes from there. Adds `.hesperus/` to `.gitignore`.
- The Hesperus sidebar is back, simpler: intent, actual and diff counts, Emit and Open Viewer, and a Create Intent From Code button when the workspace has no intent.

## 0.1.0

First release: language support through hesperus-lsp, the Intent / Actual / Unified viewer, and the emit command.
